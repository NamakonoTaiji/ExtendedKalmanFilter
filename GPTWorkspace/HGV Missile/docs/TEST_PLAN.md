# HGV機動対艦ミサイル試験計画

## 1. 目的

HGV対艦ミサイルが、限定レーダー探索、SAM判定、上下蛇行、ビーム回避、シースキミング、ポップアップ、終末誘導を再現可能に実行できることを確認する。防空ミサイルの命中率はHGV単体試験完了後の連携評価で扱う。

## 2. 試験前に記録する設定

- 使用Luaと版
- 機体構成・質量・推進・制御面
- 発射方法
- Composite配線図とノード数
- 初期位置・姿勢・速度
- データリンク敵艦位置・速度・ID
- レーダーFOV、射程、探知間隔
- PPN / PNゲイン
- 上下蛇行の高度振幅
- 重力補償と最大フィン指令
- シースキミングモード入力とRadar→Guidance Bool ch5配線
- 天候・風など

未確定値は推測せず `TBD` とする。

## 3. 最低限の観測値

- tickと飛行経過tick
- SEARCH / CANDIDATE / EVADE / TERMINALと、TERMINAL内部のPOPUP / DIVE
- 世界位置 X,Y,Z
- 世界速度 Vx,Vy,Vzと速度
- Physics Sensor世界位置の差分から求めた実加速度と、SAM LOSに直交する実横加速度
- 姿勢、角速度
- 敵艦水平距離
- レーダー指向方位・仰角
- レーダー観測数とSAMトラックID
- SAM推定位置・速度・相対接近判定
- Yaw / Pitch指令と飽和
- 通常基準高度2000 mまたはシースキミング高度20 mからの偏差
- 候補、脅威確定、失探、通過、終末遷移イベント
- 飛行終了理由

診断は `debug.log` で取得し、デバッグ専用Composite出力は追加しない。

## 4. オフライン検証済み項目

2026-08-25の初版に加え、2026-08-27までのSEARCH仰角、SAM速度基準ビーム指令、シースキミング状態遷移、通常HGVのEVADE上下蛇行をLua 5.3で確認済み。

- 敵艦方位に対する `-20度 / 0度 / +20度` の3点探索
- SEARCH垂直ビームが敵艦仰角と水平0度の両方を含み、TERMINALでは敵艦仰角へ直接指向すること
- 水平距離1500 mでのTERMINALラッチ
- シースキミング時だけ水平距離1000 mでTERMINALラッチすること
- 300 m/s接近目標の脅威化
- 3 tick失探での解除
- 最接近点通過での解除
- 通常HGVのSEARCH/EVADEで90 tickごとに上下反転すること
- CANDIDATE中の上下蛇行停止
- SAM推定水平速度が変化しても水平指令が毎tick直交し、通常HGVでは上下蛇行を同時実行すること
- Bool ch2からBool ch5へのモード信号パススルー
- シースキミング時は設定高度を指令し、EVADE中も上下蛇行を行わないこと
- プロパティ指定ポップアップ高度到達または目標3D距離700 m未満のどちらかでDIVEをラッチすること
- LifeBoat圧縮後の主要状態遷移

これらはコードロジックの確認であり、Stormworks飛行結果ではない。

## 5. Stormworks試験順序

### T0 — センサー・配線・符号

- 生レーダー4ch/目標をLua用3ch/目標へ正しく再配置する
- 静止時のPhysics Sensor位置・姿勢を確認する
- ローカルX右、Y上、Z前を検証する
- Yaw / Pitchフィンの正負を確認する
- レーダー指向入力と出力観測角がturnsであることを確認する
- 入力からレーダー、Lua、フィンまでのtick遅延を測る

### T1 — 機動なし基準飛行

- `VERTICAL_MANEUVER_AMPLITUDE_M = 0`
- データリンク敵艦方向へ飛行する
- 高度2000 mを維持する
- 速度、高度、軌道、指令飽和を記録する

### T2 — レーダー探索

- 迎撃ミサイルを発射せず、既知位置の試験目標を敵艦方位-30度、0度、+30度へ配置する
- 3点走査が3 tickで一巡することを確認する
- ビーム境界で未探知角がないことを確認する
- 敵艦仰角から水平0度までが垂直ビーム内に入ることを確認する
- `STATUS` の指向角、`observations`、`stored_tracks`、`r1_m`～`r6_m`を記録する
- 敵艦を候補SAMとして選ばないことを確認する

### T3 — 上下蛇行

- 防空ミサイルなしで実施する
- 小さい高度振幅から開始し、1回の実験で振幅だけを変える
- 90 tickごとの指令反転と実際の高度反転の遅延を測る
- 速度低下、飽和、地面・海面接触がない範囲を採用する

### T4 — SAM判定

- 249 m/sと250 m/s以上を比較する
- HGV方向、横切り、遠ざかる進路を比較する
- CANDIDATEからEVADEまでの確認時間を測る
- 距離ノイズとRCS順入れ替わりで誤追跡しないことを確認する

### T5 — ビーム機動

- 1機のSAMだけを使用する
- 左右どちらのビーム方向を選んだか記録する
- 敵艦方向への進行成分が大きい側を選ぶことを確認する
- `GUIDANCE_STATUS` の `beam_aspect_deg` を記録し、接近中も実際のHGV水平速度とSAM推定水平速度が約90度を保つことを確認する
- 90度から外れる場合は、基準幾何ではなく機体の旋回遅れ・Yaw飽和・速度推定誤差を切り分ける
- 通常HGVではビーム機動中も90 tickごとに上下指令が反転することを確認する
- シースキミングでは同じSAM条件でも上下指令を重ねないことを確認する
- 失探3 tickと最接近点通過の解除を別々に確認する
- 回避終了後にSEARCHへ戻ることを確認する

### T6 — 終末誘導

- 水平距離1501 mと1500 mを比較する
- 高度差を変えても水平距離だけで遷移することを確認する
- TERMINALが解除されないことを確認する
- レーダーが毎tick敵艦方向へ指向することを確認する
- EVADE中に1500 mへ入った場合、TERMINALが優先されることを確認する

### T7 — シースキミング

- Radar Bool入力ch2のOFF/ONを比較し、Guidance Bool入力ch5へ同じ値が届くことを確認する
- SEARCH、CANDIDATE、EVADEで `SEA_SKIM_ALTITUDE_M` を維持し、上下蛇行しないことを確認する
- `SEA_SKIM_POPUP_RANGE` の境界前後を比較し、境界でレーダーが敵艦へ固定され `SEA_SKIM_POPUP` が出ることを確認する
- `SEA_SKIM_POPUP_ALTITUDE`へ先に到達するケースと、目標3D距離700 m未満へ先に入るケースを別々に実施する
- `SEA_SKIM_DIVE` の `reason=altitude` / `reason=range` と、その後の敵艦への比例航法を確認する
- 現行高度10 mで海面接触せず、ポップアップ中にPitch指令が飽和しないことを確認する

### T8 — 防空ミサイル連携

- 無機動を基準にする
- 上下蛇行のみ、ビーム回避のみ、複合機動を比較する
- 1回の比較で機動条件を1つだけ変更する
- HGV側と防空側のログtickを合わせる
- SAMが500 m以内に入ったらHGV側`KINEMATICS`を毎tick取得し、DebugView++左端の時刻でAA側`PN_TERMINAL`と揃える
- HGV側`actual_lateral_accel_mps2`とAA側`target_lateral_accel_mps2`を比較し、AA側だけが急増する場合はKF速度補正、両方が急増する場合は実機動を主因候補とする
