# ビーム機動追尾テスト計画

## 1. 目的

「比例航法中に終末誘導用レーダーから目標が外れる」という現象を、再現可能な条件と計測値で確認し、改善前後を同じ基準で比較する。

## 2. 最初に記録する設定

- ミサイルのビルドまたはLuaコミット
- `ADSV3 Missile.lua` と `ADSV3 MissileKF.lua` の版
- 終末レーダーの水平FOV、垂直FOV、オフセット
- `RADAR_EFFECTIVE_RANGE`
- `MISSILE_FIN_DISTANCE_THRESHOLD`
- `MISSILE_RADAR_MAX_ANGLE`
- `PN_FIN_STRENGTH`
- `PN_GAIN_SCHEDULE_ENABLE`
- `PPN_FIN_STRENGTH`
- `LOGIC_DELAY`
- EKF・ゲート関連プロパティ
- ミサイル速度、目標速度、高度、初期距離

## 3. 最低限必要な観測値

可能なら60 Hzで記録する。すべて取得できない場合も、取得できた項目を実験記録に明示する。

- tickまたは経過秒
- ミサイル位置・速度・姿勢
- 目標の真値または基準位置・速度
- EKF推定位置・速度
- レーダー検出bool
- レーダー観測の方位角・仰角
- `radarManualSweepX/Y`
- `missileRadarIO`
- 現在の誘導モード（pursuit / PN）
- yaw/pitchフィン指令
- 目標までの距離と接近速度
- epsilon、トラックID、連続ロストtick
- 最接近距離または命中結果

## 4. 主要指標

数値の合格基準は、基準試験を見てから決定する。

### FOV余裕

各軸について次を記録する。

```text
水平角度誤差 = wrapTurns(目標方位角 - ビーム指向方位角)
水平FOV余裕 = 水平半FOV - |水平角度誤差|
垂直FOV余裕 = 垂直半FOV - |目標仰角 - ビーム指向仰角|
```

`wrapTurns` は方位角差を `[-0.5, 0.5)` turnsへ折り返す。FOVと角度は同じ単位にそろえてから計算する。

負値になった軸では、目標が設定FOV外にある。

### 観測継続性

- 最長連続ロストtick
- 合計ロストtick
- 初回FOV離脱から再捕捉までのtick
- 終末誘導開始後の観測維持率

### 迎撃結果

- 最接近距離
- 命中・近接信管・自爆・失敗の別
- 初回FOV離脱距離
- 誘導指令の飽和または振動の有無

## 5. 基準シナリオ

他の条件を固定し、機動方向だけを変える。

1. 正面接近・無機動
2. 左ビーム機動
3. 右ビーム機動
4. 上方向の回避
5. 下方向の回避
6. 左ビームから右へ反転
7. 右ビームから左へ反転

左右対称条件で結果が大きく異なる場合は、座標符号、レーダー指向符号、フィン符号を優先して確認する。

## 6. 比較実験の原則

- 1回の比較で変更する要因は原則1つにする。
- 同じ初期条件と同じ機動開始条件を使う。
- ランダム要素がある場合は複数回行い、全試行を残す。
- 成功例だけでなく失敗例も保存する。
- 現行版をA、変更版をBとして、同じ表で比較する。

## 7. 初期の切り分け順

基準試験でFOV離脱を確認した後、次の順に単独変更を検討する。

1. 計測だけを追加し、現象の時系列を確定する
2. ハンドオフ距離または時期
3. レーダービーム指向と遅延補償
4. PNとpursuitの切替条件
5. 目標ロスト時の誘導・再捕捉
6. EKF予測とデータアソシエーション

### 固定中主トラックの方向ペナルティ除外試験

変更前をA、固定中の主トラックだけ進行方向ペナルティを除外した版をBとする。HGVのビーム機動＋上下蛇行、近接信管設定、`LOGIC_DELAY`、KFプロパティ、機体をそろえて各10回以上比較する。命中率に加えて、終末100 m以内の`raw_observations`、予測だけになった連続tick、`track_changed`、最接近距離を記録する。Bでも通常の`D_ASOC_EPS`ゲートは残るため、観測割当が途切れる場合はゲート閾値または予測共分散を別の単独変更として検討する。

### 自機位置遅延補償の対照試験

目標だけを `LOGIC_DELAY` 分予測していた変更前をA、自機位置も同じ時間だけ予測する変更後をBとする。プロパティ、初期条件、目標機動は変えず、次を最低3回ずつ比較する。

1. 正面接近
2. 後方からの追尾
3. ビーム機動
4. 後方追尾中の近距離旋回

特に、最接近前後のyaw/pitch指令の振動、レーダーロスト、最接近距離、命中または自爆を比較する。`LOGIC_DELAY` 自体を0へ変えると目標予測も同時に無効になるため、位置補償だけのA/B比較には使わない。

`LOGIC_DELAY=4` の後方追尾A/B試験と複数回の反復試験を完了し、自機位置遅延補償を正式採用した。代表結果は `experiments/001-self-position-delay-compensation.md` を参照する。他の接近方向・機動条件は引き続き退行試験として扱う。

その後、全接近角度と `LOGIC_DELAY=3～5` を試験し、すべての条件で高い命中率を確認した。3、4、5の明確な差は判別できなかったため、基準値は中央の4 tickを維持し、最適値とは断定しない。詳細は `experiments/002-aspect-and-logic-delay-regression.md` を参照する。

### 自機姿勢遅延補償の対照試験

自機位置までを予測する正式採用版をA、自機姿勢も同じ `LOGIC_DELAY` tick先へ予測する試験版をBとする。`LOGIC_DELAY=0` は目標・位置予測も同時に変わるためA/B切替には使わず、姿勢予測実装前のビルドと現在のビルドを同一条件で比較する。

1. 無機動目標への正面接近
2. 無機動目標の後方追尾
3. 左右の回避目標
4. 上下の回避目標
5. 最接近直前にミサイル自身の角速度が大きくなる条件

まず `LOGIC_DELAY=4` で各条件を最低3回比較し、次に3と5で退行を確認する。命中率、最接近距離、最長レーダーロスト、最小FOV余裕、最接近前後のyaw/pitch指令の振動を記録する。特に、姿勢予測が必要ない正面接近・無機動条件の命中率を悪化させないことを確認する。初回tickは履歴がないため現在姿勢へフォールバックする。

オフラインでは、静止姿勢、一定yaw、クォータニオンの符号反転、正規化、`LOGIC_DELAY=0` を確認済み。ゲーム内試験の結果が得られるまでは、姿勢予測を性能改善として正式採用済みとは扱わない。

### 300～100 m限定PNゲインスケジュールの対照試験

`LOGIC_DELAY=3`、`PN_FIN_STRENGTH=1.0`を固定し、`PN_GAIN_SCHEDULE_ENABLE=false`をA、trueをBとする。ビーム機動＋上下蛇行HGVへ同じ初期条件で各10射以上を交互に実施し、命中率、最接近距離、100 m以内の操舵振動、FOV・観測継続、トラック交換を比較する。

Bでは距離300～100 mかつLOSから求めた相対横速度相当値80 m/s超でだけ`pn_schedule`が正になる。距離250～150 m、相対横速度相当値160 m/s以上で実効`pn_gain=1.5`となり、100 m以下では必ず基準ゲインへ戻ることを確認する。`PN_FIN_STRENGTH=1.2`を試す場合は別群とし、1.0の結果と混ぜない。対水上モードではtrueでも`pn_schedule=0`を維持する。

### 終末レーダー起動角度ラッチ

`MISSILE_RADAR_MAX_ANGLE=40` とし、距離条件が初めて成立するtickの直前・直後で次を確認する。

1. 目標速度方向と目標からミサイルへの方向がなすアスペクト角が39.9°なら `missileRadarIO=true` になる。
2. 角度が40.0°および40.1°なら `missileRadarIO=false` のままになる。
3. 40.0°以上で一度起動を拒否された後、40°未満へ正対しても `missileRadarIO=false` を維持する。
4. 距離条件成立前に40°以上となり、成立時までに40°未満へ正対した場合は起動する。
5. ミサイルの機軸が目標LOSから外れていても、目標進行方向に対するアスペクト角が40°未満なら起動する。
6. 目標速度が0.1 m/s以下で進行方向を定義できない場合は、角度0°として起動を許可する。

## 9. 組み込みデバッグログ

誘導状態のログは `ADSV3 Missile.lua` の `updateGuidanceDebug()` に集約している。接頭辞は `[AA_DBG]`。

- `PN_START`：最初にPNへ入ったtickと距離
- `TERMINAL_RADAR_ON`：終末レーダー有効化tickと距離
- `RADAR_LOST_START`：既存の目標検出boolがOffになり始めたtick
- `RADAR_REACQUIRED`：既存の目標検出boolが再びOnになった時点と、直前の連続ロストtick数
- `PN_TERMINAL`：500 m以内のPN中に毎tick記録するLOS角速度、LOS由来相対横速度相当値、実効PNゲイン、スケジュール係数、重力補償前後の操舵指令、ミサイルフィン入力範囲±10超過、閉速度、推定残り時間、目標推定横加速度
- `CLOSEST_PASS`：500 m以内へ進入後の最小距離。最小値から50 m以上離れた状態が3 tick連続してから確定する
- `STATUS`：終末誘導中の1秒ごとの集計
- `FINAL`：自爆時の最終集計

`PN_TERMINAL` の `los_yaw_rad_s` / `los_pitch_rad_s` は自機予測姿勢基準のLOS角速度、`pre_gravity_yaw` / `pre_gravity_pitch` は終末レーダー検出による抑止判定後かつ重力補償前、`output_yaw` / `output_pitch` は重力補償後に実際の出力チャンネルへ渡す値である。`yaw_over_limit` / `pitch_over_limit` はこの最終値がミサイルフィンの有効入力範囲である絶対値10を超えたかを表す。

`los_lateral_speed_mps`は誘導に使用した距離へLOS角速度ベクトルの大きさを掛けた相対横速度相当値、`pn_gain`は実際にLOS yaw/pitchへ掛けたゲイン、`pn_schedule`は0～1の追加ゲイン係数である。スケジュール無効、対水上、300 m以上、100 m以下、または相対横速度相当値80 m/s以下では0となる。

`closing_speed_mps` は正値が接近、負値が離隔である。`tgo_s` は現在距離を正の閉速度で割り、接近していない場合は `-1` とする。`target_lateral_accel_mps2` はKF出力の目標速度を1 tick差分して求めた加速度から、現在LOSと平行な成分を除いた大きさであり、推定値の急変も含む診断値として扱う。

`CLOSEST_PASS` は発射直後の距離揺れを拾わないよう、500 m以内へ入るまで判定を開始しない。さらに1 tickの推定値ジャンプで確定しないよう、最小距離から50 m以上離れ、かつ距離増加が3 tick連続した時点で記録する。`min_distance_m` は誘導Luaが使用する遅延補償後の推定距離であり、目標真値による実測ミス距離ではない。

FOV計測は別Luaブロックの `ADSV3 MissileFOVDebug.lua` に集約している。接頭辞は `[AA_FOV]`。

- `WAIT_TARGET_ID`：終末レーダー有効後も発射前に記憶すべき対象ID・座標を取得できていない
- `MONITOR_START`：終末レーダー有効化信号または最初の生レーダー観測による計測開始、FOV設定、指向命令遅延
- `FOV_EXIT_FIRST` / `FOV_EXIT`：FOV離脱、離脱軸、角度誤差、FOV余裕
- `FOV_REENTER`：FOV内への復帰
- `RADAR_ACQUIRED`：対象に最も近い生レーダー観測を初めて取得
- `RADAR_LOST_START`：対象に対応する生レーダー観測がなくなった最初のtick。直前の生レーダー観測と現在のデータリンク推定について、適用指向tick、角度誤差、FOV余裕、参照角度差を同じ行へ記録する
- `RADAR_REACQUIRED`：生レーダー観測の再捕捉と直前の連続ロストtick数
- `DELAY_SCAN`：ロスト直前または再捕捉時の同一生レーダー観測について、ロガーで0～3 tick前に受信した指向角それぞれの角度誤差とFOV余裕を並べて記録する
- `KF_STATE`：計測開始後の毎tick。前tick位置・速度による1 tick予測からの位置残差、KF速度の1 tick変化、AAミサイルの実速度・実加速度、各値のLOS直交成分、推定閉速度、相対横速度、速度ベクトル交差角、LOS仰角、トラック有効・切替状態を記録する
- `STATUS`：1秒ごとのFOV余裕、観測数、最長ロストの集計

現在の配線ではKF指向角が2 tick、同じ終末レーダー観測が1 tick遅れてロガーへ届く。この経路差に合わせ、主FOV判定は現在の目標視線角とロガーで `1 tick` 前に受け取った指向角との差から算出する。有効化命令は3 tick遅れるため、生レーダー観測が先に届いた場合も計測を開始する。遅延較正中は`DELAY_SCAN`で0～3 tick前の候補も併記し、生レーダーが検出できている観測に整合する遅延を比較する。

ロガーは発射前の `100000 + 目標ID` を記憶し、発射後の時分割データリンクから一致するIDの座標だけを採用する。対象座標が送られないtickは、直近2回の一致座標から求めた速度で補間する。ログの `target_id` と `data_age_ticks` で選択対象と最終更新からの経過を確認できる。

生レーダー観測があるtickは、選別済みデータリンク目標に角度・距離が最も近い観測を使用し、観測がないtickは補間したデータリンク目標角を参照する。ログの `reference=radar` / `reference=datalink` で区別できる。

複数の別目標が近接している場合、独立ロガーの選択結果がKF内部のデータアソシエーションと一致しない可能性がある。最初の基準試験は単一目標で実施する。

`KF_STATE`の`position_residual_m`は、今回位置と「前tick位置＋前tick速度×1/60秒」の差である。`lateral_position_residual_m`はその現在LOS直交成分、`velocity_step_mps`と`lateral_velocity_step_mps`はKF推定速度の1 tick変化である。`missile_speed_mps`と`missile_velocity_x/y/z_mps`は自機世界座標位置の1階差分による実速度、`missile_accel_mps2`は2階差分による実加速度、`missile_lateral_accel_mps2`はそこから現在LOS平行成分を除いた横加速度である。`est_closing_speed_mps`は正値が接近、`est_relative_lateral_speed_mps`はKF LOS直交方向の相対速度、`est_velocity_cross_angle_deg`はAA速度とKF目標速度の角度で0°が同方向、90°が直交、180°が正面反航、`los_elevation_deg`は世界水平面に対するKF LOS仰角である。推定幾何量は`LOGIC_DELAY`補償済み目標速度とパススルー自機位置差分速度を組み合わせるため、厳密な実速度同士の角度は同時刻のHGV側`KINEMATICS`とAA実速度3軸を使う。FOVロガーがKF出力を読む固定遅延を含むため、`PN_TERMINAL`との照合はDebugView++左端の時刻を基準にする。HGV側`KINEMATICS`とも同様に時刻を合わせ、目標とAAの実横加速度、KF速度変化、操舵飽和の順序を比較する。`kf_track_valid=false`または`track_changed=true`の行は、同一トラックの連続EKF更新とは分けて扱う。

デバッグ定数は `ADSV3 MissileFOVDebug.lua` 冒頭に集約している。現在は水平FOV全幅 `18°`、垂直FOV全幅 `86.4°`、垂直オフセット `0°`、主判定の指向履歴 `1 tick`、遅延較正候補 `0～3 tick`、KF状態ログ有効。追加のデバッグ用outputは使用しない。

LifeBoat既定設定での圧縮実測は、`ADSV3 MissileKF.lua` が `8185` 文字、`ADSV3 MissileFOVDebug.lua` が `7416` 文字、`ADSV3 Missile.lua` が `8142` 文字。各Luaブロックは8192文字以内。
