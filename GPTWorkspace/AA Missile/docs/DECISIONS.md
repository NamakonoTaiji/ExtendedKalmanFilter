# 設計判断記録

採用した判断だけを時系列で残します。検討中の案は実験記録または `PROJECT_PLAN.md` に置きます。

## 記入形式

```markdown
## YYYY-MM-DD — 判断の短い名前

- 状態：採用 / 破棄 / 置換
- 背景：何が問題だったか
- 判断：何を選んだか
- 根拠：どの実験・観測・制約に基づくか
- 影響：変更するファイル、プロパティ、配線、試験
- 代替案：検討したが選ばなかった案
```

## 2026-08-23 — 計測優先の進め方を採用

- 状態：採用
- 背景：ビーム機動時の追尾低下とFOV離脱は確認されているが、時系列の計測値と支配要因は未整理。
- 判断：誘導則の変更前に、現行版の基準試験とFOV余裕・観測ロスト・最接近距離の記録を行う。
- 根拠：複数の候補要因を同時に変更すると、改善理由と退行原因を判別できないため。
- 影響：`docs/TEST_PLAN.md` と `experiments/` を全変更の比較基準とする。
- 代替案：直ちにPNゲインや誘導切替を調整する案は、基準計測後まで保留。

## 2026-08-24 — FOV計測をKF側の遅延指向角比較へ置換

- 状態：置換
- 背景：誘導Luaで推定目標角と同じ推定値から作った指向命令を比較すると、誤差が常にほぼゼロとなり、FOV余裕を測定できなかった。
- 判断：レーダーは命令角へ正確に指向するものとし、プライマリの生レーダー観測を初めて取得してから、現在の目標視線角と2 tick前の指向命令をKF側で比較する。レーダー観測がプライマリへ割り当てられたtickは生観測角、それ以外はデータリンク目標角を参照する。
- 根拠：ゲーム内レーダーには指向ノイズや機械的追従誤差がなく、考慮対象は約2 tickのロジック遅延であるという運用条件。
- 影響：`ADSV3 MissileKF.lua` が軽量CSV形式の `[F]` ログを担当し、`ADSV3 Missile.lua` は誘導イベントの `[AA_DBG]` ログだけを担当する。デバッグ用outputは追加しない。LifeBoat圧縮時もKFは8192文字を超えるため、別Luaブロックへの分離を次の候補とする。
- 代替案：誘導Luaで同tickの推定角と指向角を比較する旧方式は、自己参照になるため置換した。

## 2026-08-24 — FOV計測を独立Luaブロックへ分離

- 状態：採用
- 背景：FOVデバッグを除いたKF本体だけでLifeBoat圧縮後8129文字あり、8192文字制限まで63文字しか残らない。軽量ログを同居させても9248文字となった。
- 判断：KF本体からFOV計測を完全に除去し、出力を持たない `ADSV3 MissileFOVDebug.lua` へ分離する。
- 根拠：KFの追跡・指向動作を変えず、KFとロガーの両方を各Luaブロックの8192文字以内に収められるため。
- 影響：終末レーダー観測、データリンク目標位置、自機位置・姿勢、KF指向角、終末レーダー有効信号を新しいLuaブロックへ再配置する。外部デバッグ出力は追加しない。
- 代替案：KFの機能を削った診断専用版は基準挙動が変わるため採用しない。

## 2026-08-24 — 独立ロガーでも追跡対象IDを選別

- 状態：採用
- 背景：発射後のデータリンクは全目標の座標を時分割送信するため、現在の座標入力を無条件に使うと別目標をFOV基準にしてしまう。
- 判断：ロガーも発射前の `100000 + 目標ID` を記憶し、発射後は一致IDの座標だけを採用する。更新間は一致座標の差分速度で補間する。
- 根拠：2026-08-24の試験で、実距離約443mに対してロガーが別目標由来の15641mを記録したため。
- 影響：`ADSV3 MissileFOVDebug.lua` のnum 31へKF入力32と同じ目標IDを接続する。指向角2 tick・レーダー観測1 tickの経路差に合わせ、指向履歴を1 tickへ変更する。
- 代替案：KFの推定目標出力を基準にするとレーダー指向命令と同一系列の自己参照へ戻るため採用しない。

## 2026-08-25 — 自機位置を目標と同じ時刻へ予測（正式採用）

- 状態：採用・反復試験済み
- 背景：目標位置だけを `LOGIC_DELAY` tick先へ予測し、自機位置は現在値のままLOSとレーダービーム指向を計算していた。後方追尾では `LOGIC_DELAY` を増やすほど目標至近の追尾が不安定になる。
- 判断：Physics Sensorの現在位置と過去2 tickの位置から、1階差分の速度と速度差分の加速度を求め、自機位置を `LOGIC_DELAY` tick先へ定加速度予測する。KFでは予測目標へのビーム指向、誘導Luaでは距離・LOS・目標相対幾何だけに使用する。姿勢の予測は今回含めない。
- 根拠：未来目標と現在自機を引くと、相対位置に自機移動量が混入する。ノイズのないPhysics Sensor位置を使えば、追加センサーやチャンネルなしで両者の時刻基準を合わせられる。`LOGIC_DELAY=4` の代表A/B試験では、変更前が149.2 mで水平FOVを離脱し主終末レーダーの生観測を最長102 tick以上ロストした後に自爆した一方、改良版は同レーダーのFOV離脱・生観測ロストなしで命中した。さらに全接近角度と `LOGIC_DELAY=3～5` の反復試験でも高い命中率を維持した。
- 影響：`ADSV3 MissileKF.lua` と `ADSV3 Missile.lua` の現行実装として維持する。生レーダー観測のローカル→世界座標変換、EKF、自機姿勢、KF出力num 13–15は現在時刻のままとし、既存配線とFOVロガーを維持する。採用根拠は `experiments/001-self-position-delay-compensation.md`、角度・遅延の退行結果は `experiments/002-aspect-and-logic-delay-regression.md` に保存する。
- 代替案：KF出力num 13–15を予測位置へ変更する案は、同出力を現在位置として使うFOVロガーを壊すため採用しない。新規出力チャンネルの追加も配線変更を伴うため採用しない。

## 2026-08-27 — 自機姿勢遅延予測を試験版へ採用

- 状態：採用・ゲーム内試験待ち
- 背景：目標位置と自機位置は `LOGIC_DELAY` tick先へそろったが、旋回中も未来の相対位置やLOS角速度を現在姿勢でローカル変換しており、姿勢だけに時刻不整合が残っていた。
- 判断：現在と1 tick前の自機クォータニオンを最短側へそろえ、その差分を角速度相当として `LOGIC_DELAY` tick先へ一次外挿して正規化する。KFでは有効トラックのビーム指向だけ、誘導Luaではpursuitの目標方向変換とPNのLOS角速度変換だけに使う。
- 根拠：Physics Sensor姿勢に観測ノイズがなく、60 Hzかつ3～5 tick程度の短い予測時間である。静止姿勢、1 tickあたり0.01 radの一定yaw、`q`/`-q`の符号反転、正規化、`LOGIC_DELAY=0` のオフライン数値試験を通過した。
- 影響：`ADSV3 MissileKF.lua` と `ADSV3 Missile.lua` を変更する。生レーダー観測、EKF、KF出力num 16–19、FOVロガー、実速度のローカル変換、重力補償は現在姿勢のまま維持する。チャンネル、プロパティ、配線、デバッグoutputは追加しない。LifeBoat圧縮後はKF 8148文字、誘導Lua 7540文字。
- 代替案：角速度・角加速度を指数写像で積分する方式は、ゲーム内A/B試験で一次外挿の誤差が確認された場合に検討する。KF出力姿勢そのものを予測値へ変える案はFOVロガーと生観測の時刻基準を壊すため採用しない。

## 2026-08-27 — KF出力の1 tick予測残差を独立ロガーで計測

- 状態：採用・診断用
- 背景：HGV実横加速度は最大約320.5 m/s²で滑らかだった一方、AA側のKF速度差分は最大17867 m/s²へ急増し、同時期にLOS角速度と操舵出力も急変した。実機動とEKF更新補正を分離する必要がある。
- 判断：`ADSV3 MissileFOVDebug.lua`で、前tickのKF位置・速度から1 tick先を予測し、今回のKF位置との差と速度変化を毎tick記録する。全量・3軸値・現在LOS直交成分に加え、トラック有効状態とID切替を併記する。
- 根拠：圧縮余裕のないKF本体を変更せず、既存KF出力の分岐だけで推定状態の不連続を直接観測できる。
- 影響：FOVデバッグ入力num 13–18へKF位置・速度、num 32へKFトラックID、bool 2へKF追跡有効信号を接続する。入力枠確保のためFOVロガーが扱う生レーダー目標を6枠から4枠へ減らす。KF本体、誘導、外部出力、プロパティは変更しない。
- 代替案：KF本体へログを戻す案は8192文字制限、別の第4Luaブロックを追加する案はブロック・配線増加のため採用しない。

## 2026-08-28 — 観測未割当時も固定中の主トラックを予測継続

- 状態：採用・ゲーム内試験待ち
- 背景：HGV終末試験では、生レーダー観測が存在する状態で固定中の主トラックへの割当が途切れ、約294 m/sの推定速度に対する1 tick移動量と一致する4.906 mの位置残差が発生した。その直後にトラックIDが12から13へ切り替わり、KF速度差分とPN操舵指令が急変した。
- 判断：観測が割り当てられなかった固定中の主トラックについて、状態`X`、共分散`P`、状態基準tickを今回の予測値まで進める。`lastSeenTick`と連続ミス数は従来どおり更新せず、ロスト判定は緩和しない。
- 根拠：未割当時に状態を保持すると、移動目標の出力位置が1 tick停止し、次回更新またはトラック切替時に不連続が生じる。予測状態を確定すれば、観測が一時的に途切れても定加速度モデルに従って連続した位置・速度を出力できる。
- 影響：`ADSV3 MissileKF.lua`の固定中主トラックのミス処理だけを変更する。チャンネル、プロパティ、トラック削除条件、データリンク選別、他トラックの挙動は変更しない。
- 代替案：全トラックを予測状態へ進める案は複数目標時のGNN挙動まで同時に変えるため保留。関連付けゲートとプロセスノイズの調整は、本変更単独の試験後に別要因として比較する。

## 2026-08-28 — 固定中の主トラックから進行方向ペナルティを除外

- 状態：正式採用・反復ゲーム内試験済み
- 背景：HGV失敗試験では生レーダー観測が毎tick存在した一方、終末で主トラックが約3 tick予測だけとなり、トラックIDが2から3へ交換された。既存の関連付けは、観測残差が推定速度方向から外れるほどepsilonを最大約3倍へ増幅するため、横機動する目標を棄却しやすい。
- 判断：発射後に固定されている主トラックの候補だけ方向ペナルティを無効化する。通常のマハラノビス距離と`D_ASOC_EPS`ゲートは維持し、固定前および他トラックには従来のペナルティを適用する。
- 根拠：失敗ログでは、FOVロガーの2 tick遅延を補正すると実距離約54 mから観測更新が途切れ、約34 mでトラック交換と推定加速度急増が発生した。変更後の単回試験では、終末130 m以内で生観測13/13、予測のみ相当0行、トラック交換0回となり、最大位置残差は10.459 mから1.030 mへ低下した。続く実用候補設定10射では9/10迎撃し、終末100 m以内の`KF_STATE`計161行すべてで生観測が存在し、トラック交換、FOV離脱、レーダーロスト開始はいずれも0だった。`LOGIC_DELAY=3`と`PN_FIN_STRENGTH=1`も同時に採用した試験なので、命中率90%そのものは本変更単独の効果とは扱わないが、関連付け安定化は反復確認できた。
- 影響：`ADSV3 MissileKF.lua`のepsilon補正条件だけを変更する。入力・出力、プロパティ、9次元CA状態、通常ゲートは変更しない。LifeBoat圧縮後は8185文字。併せてミサイルフィンの実入力範囲に合わせ、`ADSV3 Missile.lua`の操舵超過ログを±1から±10へ訂正した。
- 代替案：9次元CAから6次元CVへ縮小する案は文字数確保に不要であり、HGV加速度を状態として保持できなくなるうえ、KF全体の再調整が必要なため今回は採用しない。`D_ASOC_EPS`の全体的な緩和は他目標への誤関連付けも増やすため、今回のA/B試験後まで保留する。

## 2026-08-28 — HGV迎撃の基準遅延とPNゲイン

- 状態：`LOGIC_DELAY=3`と`PN_FIN_STRENGTH=1.0`を基準値として採用
- 背景：方向ペナルティ除外後、遅延3・ゲイン1.0では9/10迎撃した一方、ゲインを固定した遅延4では2/10となり、目標後方で炸裂する例が多かった。遅延3・ゲイン1.5～2.0では一定数命中するが、後追い時の目標至近で操舵が荒れて外れた。遅延3・ゲイン1.0～1.2が現時点で最良だった。
- 判断：定量ログのある遅延3・ゲイン1.0をHGV迎撃の運用基準とする。1.1～1.2は追加反復まで候補値とし、遅延4と1.5以上の高ゲインは現構成の基準にしない。
- 根拠：終末100 mで生観測161/161、FOV離脱・レーダーロスト・トラック交換0を維持したうえで9/10迎撃した。目標位置予測だけを4 tickへ延ばした分離試験では6/10、全予測4 tickでは2/10だった。`LOGIC_DELAY`は目標予測、自機位置・姿勢予測、レーダー指向と起動判定を共用しており、配線遅延段数そのものではない。目標・自機の定加速度外挿に含まれる加速度項は遅延の二乗に比例するため、3から4への変更で約1.78倍となり、旋回中は4 tick外挿が過大補償となる可能性がある。段階的な9/10、6/10、2/10という結果から、目標の長すぎる外挿が悪化要因の一部であり、他の4 tick予測との複合影響もあると判断する。
- 影響：コード、配線、入出力は変更しない。Stormworks側プロパティ設定だけに適用する。詳細は`experiments/004-hgv-guidance-delay-gain.md`へ保存する。
- 代替案：目標予測の単独分離試験は完了した。さらに原因を分ける場合は、目標を3 tickに戻し、自機位置のみ4 tick、自機姿勢のみ4 tickを診断用に比較する。

## 2026-08-28 — 終末レーダー起動時の正対角度ラッチ

- 状態：採用・ゲーム内試験待ち
- 背景：終末レーダーの距離条件へ到達しても、ミサイルが目標へ十分に正対していない場合がある。この状態で終末レーダーを起動させず、その後に姿勢が改善しても再判定で起動させない運用が必要になった。
- 判断：距離・モード・発射済み条件が初めて成立したtickに、目標速度方向と「目標からミサイルへの方向」がなす3次元アスペクト角を求める。目標がミサイルへ真っすぐ向かう状態を0°とし、角度が `MISSILE_RADAR_MAX_ANGLE` 以上なら無効ラッチを立て、その発射中は `missileRadarIO` を有効化しない。未設定または0以下のしきい値は40°とする。目標速度が0.1 m/s以下で進行方向を定義できない場合は起動を許可する。
- 根拠：ここでの「正対」はミサイル機軸と目標LOSの関係ではなく、目標の進行方向に対する迎撃アスペクトを意味する。距離条件成立前の一時的な角度超過は拒否理由にせず、指定された起動判定時点だけを評価する。
- 影響：`ADSV3 Missile.lua` と数値プロパティ `MISSILE_RADAR_MAX_ANGLE` を追加する。入力・出力チャンネルおよび対水上モードの挙動は変更しない。39.9°の起動、40.0°の拒否、拒否後のラッチ保持、距離条件成立前の非ラッチ、ミサイル機軸からの独立性、停止目標の起動許可、未設定時の40°既定値をLua 5.3でオフライン確認済み。LifeBoat既定設定で圧縮後7824文字。Stormworks内の統合動作は未確認。
- 代替案：角度がしきい値未満へ戻ったら後から起動する方式は、「二度とtrueにしない」という運用要件を満たさないため採用しない。ミサイル前方軸と目標LOSのオフボアサイト角を使う方式は、ユーザーが指定した目標進行方向基準ではないため置換した。

## 2026-08-28 — 交差コースの速度幾何を独立ロガーで計測

- 状態：採用・診断用
- 背景：LOSが垂直に近い交差コースで迎撃失敗が増える傾向を確認したが、従来ログにはAAミサイルの実速度ベクトルがなく、両機の速度交差角とLOS直交方向の相対速度を数値確認できなかった。
- 判断：`ADSV3 MissileFOVDebug.lua`の`KF_STATE`へAA実速度3軸、推定閉速度、推定相対横速度、AA速度とKF目標速度の交差角、世界水平面基準のLOS仰角を追加する。交差角は0°を同方向、90°を直交、180°を正面反航とする。
- 根拠：既存の自機位置差分速度とKF位置・速度だけで、追加配線や誘導処理の遅延を発生させずに終末幾何を毎tick観測できる。

## 2026-08-28 — 300～100 m限定の対空PNゲインスケジュール

- 状態：試験採用・ゲーム内A/B待ち
- 背景：直交交差の失敗ログでは、終末500 m以内の生観測・主トラックを維持したまま、相対横速度が498 mの25.4 m/sから58 mの204.0 m/sへ増えた。58 m以近では、AA速度をLOS角速度で回す運動学的要求目安がAA実横加速度を上回った。固定ゲイン1.5～2.0は至近振動を起こしたため、補正時期だけを前倒しする必要がある。
