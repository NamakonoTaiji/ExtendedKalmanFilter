# 防空ミサイル性能向上プロジェクト

Stormworks上の防空ミサイルについて、ビーム機動を行う目標への追尾性能を改善するための作業場所です。

## 現在の課題

比例航法中に目標が終末誘導用レーダーの視野角から外れ、観測の継続性が失われることで追尾が甘くなる問題を扱います。

## 現在の採用版

目標位置と自機位置をともに `LOGIC_DELAY` tick先へそろえる位置予測を正式採用しています。`LOGIC_DELAY=4` の後方追尾では、変更前に発生した近距離FOV離脱・長時間ロスト・自爆が解消されました。さらに全接近角度と `LOGIC_DELAY=3～5` の反復試験でも高い命中率を維持しています。代表A/B結果は `experiments/001-self-position-delay-compensation.md`、角度・遅延の退行結果は `experiments/002-aspect-and-logic-delay-regression.md` に記録しています。

現在は次の試験版として、自機クォータニオンの1 tick差分から `LOGIC_DELAY` tick先の姿勢も予測しています。KFの追跡中ビーム指向と、誘導Luaのpursuit/PN座標変換だけに適用し、生レーダー観測、EKF、FOVロガー、重力補償は現在姿勢のままです。オフライン数値試験は完了していますが、ゲーム内の命中率と退行確認は未実施です。

HGV交差コース用の次の診断版として、対空PNの300～100 mだけ有効な限定ゲインスケジュールも実装しています。`PN_GAIN_SCHEDULE_ENABLE=true`で有効になり、LOS角速度から求めた相対横速度相当値が80～160 m/sへ増えるにつれて、実効ゲインを`PN_FIN_STRENGTH`から1.5へ滑らかに近づけます。基準ゲインが1.5以上なら追加増幅しません。100 m未満、300 m以上、対水上モードでは従来ゲインのままです。HGV試験の`LOGIC_DELAY`は一貫して3です。

現段階では、いきなり誘導則を変更するのではなく、次の順序で進めます。

1. 現行挙動を再現する
2. 視野角離脱が起きる時刻・距離・角度を記録する
3. レーダー指向、誘導切替、目標推定のどこが支配的か切り分ける
4. 変更を1つずつ比較する
5. 複数条件で退行がないことを確認する

## 現在の主要ファイル

- `ADSV3 MissileKF.lua` — レーダー観測、データアソシエーション、EKF、レーダービーム指向
- `ADSV3 Missile.lua` — 発射後の誘導、単追尾・比例航法、終末レーダーへの切替
- `ADSV3 MissileFOVDebug.lua` — 別LuaブロックでFOV余裕とレーダー観測ロストをDebugViewへ記録（出力なし）
- `Stormworks 概要 (v7).docx` — Stormworksのレーダー、座標系、Lua制約などの原典
- `AGENTS.md` — Codexがこのフォルダで守る作業ルール
- `docs/PROJECT_PLAN.md` — 目的、現状、マイルストーン、未確定事項
- `docs/INTERFACES.md` — Lua間の入出力チャンネルとプロパティ
- `docs/TOOLING.md` — 現在利用できる編集・検証環境
- `docs/TEST_PLAN.md` — ビーム機動を中心とした検証計画
- `docs/DECISIONS.md` — 採用した設計判断の履歴
- `experiments/` — 実際の試験条件と結果

## 作業開始時

Codexには、まず次のように依頼できます。

> AA MissileのAGENTS.mdとPROJECT_PLAN.mdを読み、現在の課題と次に行うべき実験を要約してください。

コード修正を依頼するときは、再現した現象、試験条件、期待する結果を可能な範囲で添えてください。情報が不足している場合は、`experiments/000-baseline-beam-manoeuvre.md` の未記入欄を埋めるところから始めます。

## 現在の作業入口

最初の実装変更より先に、基準となるビーム機動試験を1回実施し、以下を確定することを推奨します。

- 終末レーダーの実設定FOV
- 目標・ミサイル双方の速度と高度
- ビーム機動の開始距離または開始時刻
- 終末レーダーが有効になる距離
- 目標ロスト時の方位角・仰角と継続tick数
- 最接近距離または命中結果
